# Правила для ИИ-агентов (Claude Code, Codex)

Этот файл читают агенты перед работой с репозиторием. `CLAUDE.md` ссылается сюда же.

## Что это

«Дневник смен водителя»: сервер отдаёт поездки и сводку за день, мобильное приложение их
показывает и добавляет новые поездки. У каждого водителя свой дневник; авторизации нет —
идентификатор водителя разделяет дневники, но не защищает их.

## Состав

| Папка | Что внутри |
|---|---|
| `data/trips.json` | образец поездок; сервер загружает его при старте |
| `server/shift_diary/domain/` | поездка, границы дня, расчёт сводки — без FastAPI и базы |
| `server/shift_diary/domain/rules.py` | правила проверки поездки и коды нарушений |
| `server/shift_diary/payload.py` | разбор входных данных: строгие типы, время только со смещением |
| `server/shift_diary/domain/driver.py` | идентификатор водителя и дневник по умолчанию |
| `server/shift_diary/storage.py` | хранилище на SQLite: дневники водителей, защита от дублей, обновление старой базы |
| `server/shift_diary/seed.py` | образец поездок: читается при старте, выдаётся каждому новому водителю |
| `server/shift_diary/api.py` | маршруты и единый формат ошибок |
| `server/tests/` | тесты сервера |

| `app/lib/core/` | сквозное: пояс сервиса и календарный день (`time/`), сеть, ошибки, тема, роутер, DI |
| `app/lib/features/shifts/domain/` | поездка, сводка, правила формы, контракт репозитория |

| `app/lib/features/shifts/presentation/` | кубиты, экран дня, форма поездки |
| `app/lib/features/drivers/` | водители на телефоне: хранение, выбор, смена |

Остальные части появляются по этапам — таблица дополняется вместе с ними.

## Команды

Сервер (из папки `server/`, нужен только `uv` — Python 3.13 он поставит сам):

```bash
uv run uvicorn shift_diary.main:app --reload   # сервер на http://127.0.0.1:8000, /docs — проба API
uv run pytest                    # тесты
uv run ruff check .              # линтер
uv run ruff format --check .     # форматирование
uv run mypy shift_diary tests    # типы, строгий режим
```

Все четыре проверки должны проходить перед каждым коммитом; разом — `make check` из корня.
Сервер в Docker, без установки Python: `docker compose up --build`.

Приложение (из папки `app/`, Flutter 3.38):

```bash
flutter run                      # на эмуляторе, против сервера на этой же машине
flutter analyze                  # анализатор
flutter test                     # тесты
flutter gen-l10n                 # после правки app_ru.arb
```

Адрес сервера задаётся при сборке: `--dart-define=API_BASE_URL=https://…`. Без него приложение
идёт на `10.0.2.2:8000` (эмулятор Android) или `127.0.0.1:8000` (симулятор iOS).

## API

| Запрос | Ответ |
|---|---|
| `GET /api/days` | дни, в которых есть поездки, и пояс сервиса (`utc_offset`) |
| `GET /api/days/{ГГГГ-ММ-ДД}` | сводка и поездки за день одним ответом |
| `POST /api/trips` | `201` новая, `200` повтор, `409` занятый `id`, `422` ошибки по полям, `400` не JSON-объект |

Чей дневник — задаёт заголовок `X-Driver-Id`; без него запрос идёт в общий дневник `demo`.

Ошибка любого вида: `{"error": {"code": "…", "message": "…", "fields": {"поле": "код"}}}`.
Коды полей перечислены в `Violation` (`domain/rules.py`) — клиент показывает по ним текст.

## Инварианты — не ломать

Каждый из них закрыт тестом. Правка, из-за которой такой тест приходится менять, почти наверняка
ошибочна.

1. **День считается в поясе сервиса**, а не в UTC и не в поясе машины. Пояс — фиксированное
   смещение из конфига (по умолчанию `+05:00`). Имя пояса (`Asia/Almaty`) не использовать: со старой
   базой поясов оно даёт `+06:00`.
2. **Поездка относится к дню своего начала**, даже если закончилась после полуночи.
3. **Время без смещения не принимается** — ни сервером, ни клиентом.
4. **Деньги — целые числа.** Никаких `float` / `double`, никакого молчаливого приведения строки
   или `true` к числу.
5. **Дубли отсекает база**, а не проверка в коде: два ограничения уникальности (по `id` и по
   содержимому поездки, оба — внутри дневника водителя) и вставка одним запросом. Проверка «есть ли такая» перед вставкой не
   атомарна — запросы идут в потоках.
6. **Повтор — не ошибка.** Та же поездка второй раз: `200` и существующая запись. Тот же `id` с
   другим содержимым: `409`.
7. **Клиент создаёт `id` поездки один раз** — при открытии формы. Повтор после обрыва связи идёт с
   тем же `id`.
8. **После обрыва связи форма разрешает только повтор.** Исход отправки неизвестен: исправленная
   поездка стала бы второй, если первая всё-таки дошла.
9. **В приложении нет `toLocal()`.** Местное время получается только из `ServiceZone`, а пояс
   сервиса приходит с сервера (`utc_offset`), не из настроек телефона.
10. **Сводку считает только сервер.** Приложение её показывает и не пересчитывает.
11. **Пока идёт отправка, форма не закрывается.** Ответ пришёл бы уже в никуда, и главный экран
    показал бы день без поездки, которая на самом деле записана.
12. **Перенос начала поездки сдвигает окончание следом.** Длительность сохраняется; поездка дольше
    суток не принимается ни формой, ни сервером — исправить запись потом нечем.
13. **Дневник нового водителя заводится вместе с образцом одной транзакцией.** Иначе одновременный
    запрос увидел бы дневник заполненным наполовину.
14. **Запросы подписываются новым водителем только после того, как выбор сохранён на телефоне.**
    Иначе после перезапуска приложение вернулось бы к прежнему водителю, а часть поездок осталась
    бы у нового.

## Соглашения

- Комментарии и документация — на русском; объясняют «почему так», а не «что делает строка».
- Сообщения коммитов: `feat(server): описание по-русски`, `fix(app): …`, `chore: …`.
- Пользователь видит понятный текст, а не текст исключения. В состоянии экрана лежит код ошибки,
  текст подставляется при показе.
- Новое правило проверки данных = код ошибки на сервере + текст на клиенте + тест.
- Архитектура приложения: `domain` → `data` → `presentation` внутри фичи; состояние — Cubit с одним
  классом состояния; в состоянии лежит код ошибки, а не текст.
- Цвета и отступы в виджетах — только из `AppColors` / `AppSpacing`, тексты — только из ARB.
- Тесты приложения — на рукописных фейках, без библиотек моков.

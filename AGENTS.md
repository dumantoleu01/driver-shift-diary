# Правила для ИИ-агентов (Claude Code, Codex)

Этот файл читают агенты перед работой с репозиторием. `CLAUDE.md` ссылается сюда же.

## Что это

«Дневник смен водителя»: сервер отдаёт поездки и сводку за день, мобильное приложение их
показывает и добавляет новые поездки. Водитель один, авторизации нет.

## Состав

| Папка | Что внутри |
|---|---|
| `data/trips.json` | образец поездок; сервер загружает его при старте |
| `server/shift_diary/domain/` | поездка, границы дня, расчёт сводки — без FastAPI и базы |
| `server/shift_diary/storage.py` | хранилище на SQLite; здесь же защита от дублей |
| `server/tests/` | тесты сервера |

Остальные части появляются по этапам — таблица дополняется вместе с ними.

## Команды

Сервер (из папки `server/`, нужен только `uv` — Python 3.13 он поставит сам):

```bash
uv run pytest                    # тесты
uv run ruff check .              # линтер
uv run ruff format --check .     # форматирование
uv run mypy shift_diary tests    # типы, строгий режим
```

Все четыре проверки должны проходить перед каждым коммитом.

## Инварианты — не ломать

Каждый из них закрыт тестом. Правка, из-за которой такой тест приходится менять, почти наверняка
ошибочна.

1. **День считается в поясе сервиса**, а не в UTC и не в поясе машины. Пояс — фиксированное
   смещение из конфига (по умолчанию `+05:00`). Имя пояса (`Asia/Almaty`) не использовать: со старой
   базой поясов оно даёт `+06:00`.
2. **Поездка относится к дню своего начала**, даже если закончилась после полуночи.
3. **Время без смещения не принимается** — ни сервером, ни клиентом.
4. **Деньги — целые числа.** Никаких `float` / `double`, никакого молчаливого приведения строки
   или `true` к числу.
5. **Дубли отсекает база**, а не проверка в коде: два ограничения уникальности (по `id` и по
   содержимому поездки) и вставка одним запросом. Проверка «есть ли такая» перед вставкой не
   атомарна — запросы идут в потоках.
6. **Повтор — не ошибка.** Та же поездка второй раз: `200` и существующая запись. Тот же `id` с
   другим содержимым: `409`.
7. **Клиент создаёт `id` поездки один раз** — при открытии формы. Повтор после обрыва связи идёт с
   тем же `id`.

## Соглашения

- Комментарии и документация — на русском; объясняют «почему так», а не «что делает строка».
- Сообщения коммитов: `feat(server): описание по-русски`, `fix(app): …`, `chore: …`.
- Пользователь видит понятный текст, а не текст исключения. В состоянии экрана лежит код ошибки,
  текст подставляется при показе.
- Новое правило проверки данных = код ошибки на сервере + текст на клиенте + тест.
